# JevFeed 设计

一个人的 TikTok，但内容是超链接。种子来自本地 Chrome 历史，候选来自种子页正文里的链接，每次由 Jev 从候选中选一个推给你。你的每一次观看行为都进入下一次决策。

## 交互（X 式时间线）
- 单列无限下滑的时间线，一条条链接卡片。卡片进入视口开始计时，从视口上方滑出即记为跳过并写入停留时长。
- 每条卡片下方：喜欢 / 不感兴趣 / 打开。点标题或"打开"在新标签页打开原文，回到页面时记录阅读时长。
- 每次请求把全部未看过的候选（API 上限 255 个选项，取最新 200 加随机 50）交给 Jev，拿回对所有候选的概率分布，取前 10 条作为一批放进流。未看的不足 5 条时请求下一批；请求串行，每次都带上此刻最新的行为记录。
- 首屏是授权页：点击"导入 Chrome 历史"才读本地 History 文件。历史不离开本机。
- 画像页可查看并删除系统学到的偏好。

## 行为信号（核心）
每张卡记录：展示时长 dwell_ms、动作 action（skip/like/dislike/open）、打开后停留 open_dwell_ms、序列位置。
每次请求 Jev：最近 15 条完整记录 + 慢变画像（喜欢/不喜欢的域名与关键词）+ 20 个候选。

## 数据流
Chrome History → seeds → 抓正文链接 → candidates（预取标题/描述）→ Jev 对全部未看候选排序 → 前 10 进 feed → 隐式反馈写回 events → 打开过的页面成为新 seed。

## 技术
Node 22 自带 sqlite；单个 Node 服务 + 一个静态页面；Jev 传输层与回答校验复用 mobile-jev。
